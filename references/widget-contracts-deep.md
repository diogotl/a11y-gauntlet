# Widget contracts: Deep tier

Implementation-depth rows. Apply them to **hand-built widgets** (plain DOM scripting, or a `div` with a role and handlers written in the project) and when the user passes `--deep`. A widget imported from a primitives or component library already gets this behaviour from the library: check the Core rows in `widget-contracts.md` and verify the app did not break the contract.

Rows are written implementation-neutrally. They describe behaviour an auditor can observe or read in code. Where a row names a **variant** or **Review**, more than one implementation is legitimate: report it only if a real user is blocked. Default severity is Serious unless a row says otherwise.

## Layers (dismissal, focus, hover, scroll lock, portals)

| ID | Contract |
| --- | --- |
| LAYER-09 | A controlled `open` prop does not make the UI lie: if the app forces a layer open so Escape cannot close it, there is another documented way to leave |
| LAYER-10 | Opening and closing do not move the page (scroll lock without layout shift), and exit animations do not keep focus trapped or `inert` applied after close. When popup content is replaced between triggers with a morph transition, the outgoing content snapshot is inert and not exposed to assistive technology until removed; only the current content is interactive |
| LAYER-11 | Backdrops and decorative parts (arrows, scrollbars, separators) are `aria-hidden="true"` or `role="presentation"` and are not announced. Focus sentinels may be tabbable only if focusing one immediately moves focus on and it is hidden from assistive technology (**variant:** some implementations expose a sentinel as a button on VoiceOver so the virtual cursor can trigger the redirect). They must not leave a user stuck on a sentinel: when no other tabbable element exists on the page, each sentinel hands focus on exactly once (no ping-pong), focus lands on the trigger and the layer closes. Sentinels around a trigger exist only for the trigger that owns the open popup and disappear on close. In a submenu, moving focus directly back to its trigger keeps it open, while tabbing out through its inside sentinel closes it, returns focus to the trigger and leaves the parent open and navigable (also when the submenu is portalled into a shadow root) |
| LAYER-13 | A layer closed with Escape does not reopen when the window regains focus and focus returns to the trigger, also after the layer has unmounted. Escape does not permanently block later hover opens: hovering the trigger again (mouse events only) reopens it normally |
| LAYER-16 | Outside dismissal details. A completed click dismisses; the opener's own trailing click does not. A press that starts inside and is released outside consumes one outside click. A cancelled pointer (`pointercancel`) or non-primary button does not count, and a right-button press never vouches for a later press-less click. A press-less click (keyboard, assistive technology, `element.click()`, or a click reporting a mouse pointer type with a zero click count, as Android assistive technology does) always dismisses, even after an earlier touch session. A press on the target's own scrollbar never dismisses. A press on another trigger of the same popup moves the popup instead. A press inside a layer opened later is not outside for the earlier one. On touch, a non-modal layer may treat a single-finger scroll-away as dismissal (see LAYER-06), but a tap on the backdrop uses completed-click semantics; either touch variant is acceptable. Touch outside-press listeners are passive so they cannot block scrolling |
| LAYER-18 | Return focus resolution: the trigger if still connected (for a programmatic open, the element focused before opening; when nothing was focused, the trigger that last owned the layer, never a stale trigger of another layer that had been open by default); otherwise the most recent previously focused element that is still connected and not hidden or inert; if that is not tabbable, its first tabbable descendant. When the trigger is removed as the layer closes, the next Tab continues from where the trigger sat in the tab sequence (modal and non-modal). When a layer opened from an item inside another popup (a select option or menu item that closes its popup) closes, focus returns to that source popup's trigger, including in browsers where pressing a button does not focus it (macOS Safari and Firefox) and when the layer stays mounted while closed. Do not steal focus back if the user moved focus to another control after opening, and do not move focus mid-open when the return target changes. Skip returning when the layer closed by hover-leave or by tabbing out. Keyboard close shows the focus ring on the target; pointer close does not. If return focus is turned off and the focused control inside the closed popup is removed, focus falls to `<body>` (a FOCUS-05 failure) |
| LAYER-19 | A modal with no tabbable elements still traps Tab (the key is swallowed, focus stays on the container). If the focused element inside is removed or hidden, focus goes to the nearest remembered tabbable, else the container, never `<body>` |
| LAYER-20 | Non-modal portalled popup: Tab from the trigger enters the popup even though its DOM is elsewhere (sentinels, or `aria-owns` to place it after the trigger in reading order); Tab past the last element goes to the next tabbable after the trigger and closes the layer, also when the popup is portalled into another document (iframe); focus leaving to an unrelated node closes it, but not when the window loses focus or when a nested layer receives focus, and a layer already closing does not report a second close. The ownership element carries no role at root level and `role="group"` when it lives inside a menu or menubar (a valid owned child); the submenu trigger itself has no `aria-owns`. A layer opened by hover (focus not inside): Tab and Shift+Tab from the trigger follow native DOM order, do not enter the popup and do not close it. A click-opened popup with focus inside: Shift+Tab lands on the trigger with the popup still open and Tab re-enters it; Shift+Tab from the trigger closes it and lands before the trigger; Tab during the exit animation behaves as if already closed |
| LAYER-21 | Under a modal, every outside branch is hidden from assistive technology except the popup's ancestors, nested portals, extra inside elements, and `aria-live` regions (with their ancestors) so announcements still work; the trigger itself is hidden with the outside siblings. An ancestor of the popup that lives in a shadow root is never hidden (the shadow host stays exposed) and script elements are left alone. Hiding is ref-counted across stacked layers, releases out of order without un-hiding content still covered by another layer, and never clobbers an `aria-hidden` the app set before (nor re-adds one the app removed). A non-modal layer does not hide outside content: it stays reachable by screen reader and keyboard. **Variant (Review):** a combobox whose input sits outside its popup hides the combobox's own trigger button from assistive technology while the popup is open, and does not hide the input group wrapper. A layer that is modal-capable but opened by hover may hide outside content from assistive technology without making it inert, so the page stays operable; report only if the page behind becomes unreachable by keyboard or pointer |
| LAYER-24 | Scroll lock: only for modal layers not opened by hover. A modal-capable layer opened by hover behaves as non-modal (no lock, no inert, backdrop does not capture pointer events) and becomes modal (backdrop with `role="presentation"`) only once the user clicks the trigger. A non-modal layer, or one whose open state is undefined (for example a re-render of a controlled value), does not lock the page. A touch-opened anchored popup does not lock the page unless it is nearly viewport-wide, so a swipe outside can dismiss it; the lock follows the currently open menu when top-level touch-opened menus hand off (a nearly viewport-wide menu locks, a narrower one releases; same for kept-mounted and unmounted popups; a reopen during the close animation keeps the touch type). Locking and release are ref-counted so stacked layers do not flicker; no layout shift (`scrollbar-gutter: stable` or compensating padding); iOS and overlay scrollbars use `overflow: hidden` only; scroll position is restored on release |
| LAYER-25 | Several triggers sharing one popup: only the trigger that owns the open popup has `aria-expanded="true"` and `aria-controls`; the others stay `false` with no controls. A menu trigger's `aria-controls` points at the `role="menu"` element when it exists. A layer opened programmatically for a named trigger wires only that trigger; one opened with no trigger (for example payload only) leaves every trigger `aria-expanded="false"` with no `aria-controls`, even when exactly one trigger exists, and a trigger that mounts while it is open does not take ownership. After a controlled close and reopen without a trigger, or after the owning root unmounts and remounts, no trigger keeps stale expanded or controls state |
| LAYER-26 | The popup name falls back to the trigger (via `aria-labelledby` the trigger id) unless an explicit `aria-label` or `aria-labelledby` is given. A rendered element with an explicit empty id contributes no id to ARIA references (never a reference to a missing id). When the element that actually renders a part carries its own id or `aria-label`, ARIA references use that id (it wins over a wrapper's id) and its label counts as explicit (no trigger-name fallback); the registered id is released when the element unmounts or the id is removed |
| LAYER-27 | Hover intent: a hover-opened layer opens when the mouse rests, not merely on entering, after the delay (touch never opens it by hover; a touch open may be delayed so a scroll start is not an open, but a touch close is never delayed). With rest-based opening, tiny pointer jitter (about 1 px per move) does not restart the rest timer and a real movement (about 10 px) does. Leaving the trigger keeps the layer open while the pointer travels a safe path toward the popup: the gap between them is always safe; a triangle from the leave point to the popup edge is safe while the pointer moves faster than about 0.1 px/ms; a slow drift closes it; a pointer that landed on the trigger or popup and then leaves both closes it; leaving through the side opposite the popup closes it; if the pointer is inside the triangle but has not landed, the layer closes after about 40 ms; any open nested child vetoes closing; an overlapping popup must not loop open and close. A nested branch stays open while the pointer crosses the gap to its child popup. Only the innermost nested trigger opens. A close delay keeps the layer open while the pointer crosses the transition, and re-entering the same trigger during the close transition reopens with no open delay. **Click on the trigger of a hover-opened layer:** a click soon after opening (an impatient click, within a short threshold) keeps it open; a click after that threshold (a patient click) closes it, and leaving the trigger afterwards does not reopen it. A click before the hover delay finishes also keeps it open. A second touch tap closes a touch-opened layer; Enter or Space on a hover-opened submenu trigger keeps it open. A pending delayed hover open is cancelled when the pointer leaves, even if only `mouseout` arrived |
| LAYER-28 | Escape ownership follows open order across all layers, including when focus is on `<body>` after a backdrop click; the default is prevented only if the close was not cancelled. Controlled `open={true}` keeps the layer open while every close request is still reported |
| LAYER-29 | IME specifics: ignore Escape when `isComposing`, `keyCode 229`, or a `compositionend` fired in the same tick (WebKit fires `compositionend` before `keydown`); a composition that spans a reopen must not dismiss; a composition dropped without `compositionend` must not leave Escape dead; list arrow handling ignores `which 229` (Chrome fires ArrowDown twice while composing); Enter with keyCode 229 neither selects nor moves the highlight. On Android, composition is always active: each change during composition is propagated (filtering follows), and a composition update that empties the input clears the highlight (and closes the popup when a click on the input does not open it) |
| LAYER-30 | Platform workaround: a menu item may carry `aria-selected` while a text input holds focus so VoiceOver arrow navigation works. It applies to every item kind (item, checkbox, radio, link, submenu trigger) but only to the highlighted one, is removed when the input blurs or unmounts, is restored on refocus, is never set on plain menus where real focus moves, and `aria-checked` on checkbox and radio items is kept. This is invalid on `menuitem` otherwise; report as **Review**, never as a failure |
| LAYER-33 | When a closing layer's unmount is deferred or taken over by the app, or a close request is cancelled by the app, then the closed state is still exposed immediately: the trigger shows `aria-expanded="false"`, the open-state marker is removed as soon as open becomes false, and the popup (listbox) stays hidden, never advertised as open or ending |
| LAYER-34 | When a layer is closed but kept mounted, then it does not react to input: swipe gestures, touch-to-focus handling and pointer handlers ignore it and its controls are not reachable. Its positioner is parked at the viewport origin with no stale transform, so reopening a large popup cannot overflow the layout viewport and make a mobile browser zoom the page out |
| LAYER-35 | When the trigger that owns an open layer is removed from the page and not replaced by a trigger with the same id, then the layer closes instead of staying orphaned; the removal counts as a close request the app may cancel, and a cancelled close keeps the layer open without a trigger. A layer does not open for a trigger that unmounted during the open delay. When the trigger is replaced by another element with the same id, or ownership moves to a trigger that has not rendered yet, the layer stays open |
| LAYER-36 | When a layer was opened by anything other than hover over its trigger (a button, default open, an imperative or programmatic call, a click), then the pointer entering and leaving the trigger or popup does not close it; only a layer opened by trigger hover closes after the pointer leaves. A press inside one hover-opened layer does not make later hover opens sticky: a later hover open still closes on leave. With nested hover layers, clicking, hovering or pressing inside a child keeps the parent open, a press that starts in the child and ends outside does not dismiss the parent, and when the child finally closes the parent closes with it once the pointer has left both |
| LAYER-37 | When one popup is shared by several triggers and was opened by touch, then hovering a sibling trigger does not swap its content and ownership stays on the tapped trigger; after a mouse open, hovering a sibling hands ownership to it |
| LAYER-38 | When a layer is opened by a gesture (the pointerdown that opened it, a press that began before opening, a drag-release from a menu item that opens a dialog, or a swipe or drag that opens a drawer), then the compatibility mousedown, mouseup and click synthesised by that gesture's own release (mouse, pen or touch, even if it arrives a task later and lands on the backdrop or a common ancestor) do not count as an outside press. A fresh press outside, a keyboard Enter click or a pointer-less virtual click afterwards does dismiss it. A press recorded in an earlier open session, or before a same-batch close and reopen, does not leak into the new session; a touch gesture that started before a reopen and later moves past the movement threshold (6 px and 12 px tested) or ends does not dismiss the reopened layer, while a new gesture does; a press seen mid-gesture survives listener re-attachment and redundant open notifications. If the opening gesture is interrupted, disabled mid-way or rejected by a controlled parent, outside dismissal is re-armed and the layer is not left stuck. Pointer-type memory from an earlier touch session does not stop a later press-less outside click from dismissing a keyboard-reopened layer |
| LAYER-39 | When layers are stacked or nested, then: a layer opened later never closes because of a press inside it while an earlier independent layer ignores presses inside the later one, but a press inside the earlier layer closes the later one; a press inside content portalled out of the popup but owned by it is not outside; after an inner layer closes through a press-drag-release item pick, one outside press still dismisses the outer layer; choosing an item in a non-modal inner layer leaves a modal outer layer open; a modal dialog opened after a popover is not outside for it (presses inside it, including the click synthesised by Enter submitting a form there, do not dismiss the popover), while a modal dialog opened before the popover is outside for it; pressing a nested dialog or popover trigger inside a hover- or click-opened panel, opening it and interacting inside it do not dismiss the parent panel (also when the pointer left the parent during the press); closing a nested layer (modal, non-modal, alert dialog) portalled into a shadow root or the body leaves the parent open |
| LAYER-40 | When a press begins on a control inside the layer that cancels the pointerdown default (a scrubber, a pointer-lock scrub control) and ends outside, then only the immediate click is suppressed and the next plain outside click dismisses the layer. A drag that ends on an element the app excluded from outside-press handling, or that starts on an inner trigger and is released outside every popup, does not consume the next outside click; an inside click in between does not consume the one-shot suppression; a click that another capture listener stops before its target does not make a later inside click dismiss |
| LAYER-41 | When deciding whether a press or click is inside a layer, then the composed event path is used, so a target inside a shadow root hosted within the layer counts as inside, a shadow-contained outside target is still outside, and the real target is resolved through nested shadow roots and slots (not the shadow host); a detached node never matches document-level ancestors. For a layer portalled into a shadow root (open or closed), a completed press outside the shadow tree and a click on another element in the same shadow tree dismiss a non-modal layer, a click on its own backdrop dismisses a modal, and a press anywhere outside a layer hosted in a shadow root (including the light page) dismisses it. When a modal layer is open, a press on an element unrelated to the app (a third-party widget appended to the page) does not dismiss it, while presses on the page's own elements outside a non-modal layer do |
| LAYER-42 | When a press on a trigger comes from assistive technology rather than a real pointer (a mouse pointerdown with 1x1 contact size and zero pressure; on Android a TalkBack press with a button flag but no pressure; on iOS a touch with sub-pixel contact size), then it is treated like a keyboard or virtual activation: focus moves synchronously and no pointer-modality assumptions are made; the same shape from a real touch or pen, or on any event other than pointerdown, is not. A virtual press moves focus to the first item; a virtual press on a submenu trigger opens it synchronously even with hover opening enabled, repeated virtual presses toggle it, the trailing click does not close it, and a press on a descendant of the trigger is attributed to the trigger; an ordinary mouse press (buttons=1) with hover opening enabled is left to hover; a virtual press on a second trigger of a shared popup switches the owner but keeps focus in the popup |
| LAYER-43 | Return-focus edge cases. When the trigger is hidden as the menu closes (an item press hides it), focus does not jump to an element behind an open modal dialog (not even its live-region ancestor), an input that autofocuses as the menu closes keeps focus, and focus moved by the item's own click handler stays where it was put. When a modal's outside press blurs focus to `<body>` and the app cancels the close to show a confirmation layer, closing the confirmation returns focus to the element that was focused inside the first modal (not body, not the trigger); a field inside a non-modal layer that blurs to body does not enter the return-focus history of an unrelated modal. When a dialog or alert dialog opened from a hovered menu item receives focus, the pointer leaving that item does not pull focus back into the menu |
| LAYER-44 | When classifying how a layer was opened or closed (for focus-ring and return-target decisions), then a click with zero detail (keyboard or assistive-technology activation) counts as keyboard, a click after a touch or pen pointerdown counts as touch or pen, a click with no preceding pointerdown counts as mouse, and the modality is reset between open sessions of a kept-mounted layer. A custom return target may depend on whether the layer closed by keyboard or pointer, and initial focus may depend on whether it opened by mouse, keyboard or touch (doing nothing for a pointer open when the app says so) |
| LAYER-45 | When a layer's anchor was last set from pointer coordinates (the layer follows the cursor) and it is then opened by keyboard or focus, then it anchors to the trigger element, not the stale pointer position, and later mouse moves do not re-anchor it |
| LAYER-46 | Scroll-lock mechanics. While a modal layer is open on touch devices, a touch drag outside scrollable content in the layer does not scroll the page behind it (even when the layer's own scroller does not overflow), a drag inside a scroller that can scroll that way scrolls normally and does not chain to the page, and touches inside nested portalled popups (a combobox list inside the layer) are left to the browser and do not start the layer's dismiss gesture. If the browser's native reveal-focused-field behaviour scrolls the locked page, the page scroll position is restored instantly (not smoothly, even with global smooth scrolling); a non-modal layer does not do this. When another overlay locks the page (by body attribute plus stylesheet, by body overflow shorthand, or by root overflow longhands) and releases after this layer opened, the page stays locked with no scrollable gap and unlocks when this layer closes; a body-only overflow lock that does not stop the viewport (the root is the scroller) is not treated as effective, so the layer locks at once |
| LAYER-47 | When a popup does not fit on its preferred side, then it flips to the side with more room and, if still too large, is capped to the available height and scrolls internally (content reachable by keyboard and pointer); once flipped it stays on that side when it later shrinks (no jumping), and it is positioned against the visual viewport so pinch zoom does not hide it |
| LAYER-48 | When a trigger is configured to open on mouse press rather than click, then it opens on mousedown for a real mouse only and the click that follows is ignored (it does not toggle the layer closed again); touch, pen and keyboard or assistive-technology activations still use the completed click, and an assistive-technology press (mousedown with zero detail) is handled synchronously |

## Lists and composites (navigation, type-ahead, grids)

| ID | Contract |
| --- | --- |
| LIST-01 | The single roving tab stop follows the element, not the index: it stays on the same element when an earlier item is removed, falls to the active or selected item (else the first enabled item or a replacement) when the highlighted one is removed, moves off an item that becomes disabled (also when disabled state resolves a render late), skips items hidden with `display:none` or marked `aria-disabled`, is re-validated when items are inserted around it, follows the new DOM order after a reorder on the next key press, and an all-disabled composite keeps a valid index so it regains a tab stop. A highlight that is index-based must not silently land on a different item: when a filter, a controlled query, a Clear press or an inserted item changes which element sits at the highlighted index, the highlight clears (Enter then does nothing); appending an item that the filter hides leaves the highlight untouched, and refocusing the input keeps the same highlighted item |
| LIST-02 | A native text input inside a composite keeps arrow keys unless the caret is at the relevant end: Shift or any text selection hands arrows back to the input; forward arrows leave only at end of text, backward arrows only at start. When arrow navigation moves focus onto a text input, its whole value is selected; the next same-direction arrow first collapses the selection and only a further arrow at the boundary leaves it; arrows typed with the caret mid-text do not move composite focus. A disabled-but-focusable input reached by arrows does not trap Tab (Tab leaves the composite, Shift+Tab returns) and does not block cross-axis travel; a mouse click on a disabled input does not move focus. **Modifiers:** Ctrl, Alt and Meta with an arrow disable composite navigation in every composite; Shift with an arrow also blocks it in tabs, toolbars and menus, but in a radio group Shift+arrow still moves focus and checks the next radio (as a native radio group does) while Ctrl, Alt and Meta do nothing. Home/End are not handled when the reference is a typeable combobox. A horizontal toolbar has at most one text input, placed last |
| LIST-06 | Grid: rows come from `role="row"`; groups in a grid expose `rowgroup` (named by their label) and the grid has no `aria-orientation`. Up/Down keep the column; a shorter or partial last row clamps the column; when the preferred cell is disabled or hidden focus falls to the nearest enabled cell on the left; disabled cells are skipped; looping is disabled when a virtualized list has gaps. With two-dimensional navigation Left/Right stay in the row (looping goes to the other end of the same row, never the next row) and mirror in RTL; ArrowLeft/ArrowRight edit the input caret while no cell is highlighted in a combobox grid; items spanning several cells are entered from the edge facing the movement; Home/End go to the first or last enabled cell (not handled when the reference is a typeable combobox); Escape is the cross-axis close key when orientation is both and closes a submenu returning focus to its parent item |
| LIST-07 | Pointer versus keyboard modality: hover highlights and focuses the item (and only after real movement, a non-zero delta); leaving the list clears the highlight and focuses the popup container, also when the pointer leaves while still inside an item clipped by the scrolling container; a pending item focus is cancelled if the pointer leaves first; touch pointerleave does not clear. Scroll-into-view only for keyboard moves (and for the selected item on open), and only as far as needed (about one item past the edge, not re-centred, not at all when visible); hovering a partially visible item never scrolls; items reached by typing, wrapping, End/Home or ArrowUp-open are revealed; horizontal lists in RTL use the correct physical margin. A zero-delta mouse move or pointerleave caused by the list scrolling under a still pointer (including while a popup fades out, and WebKit) must not move or clear the highlight; a synthetic mouseleave from touch must not clear the selected item's highlight on reopen; a touch scroll starting on the highlighted item keeps it. The pointer can take the highlight back after keyboard navigation and arrows continue from the hovered item. With hover highlighting off, hover neither highlights nor clears the keyboard highlight. A native press on an item focuses it before mouseup and click, even with hover highlighting off, and releasing on a disabled item focuses it without activating. When the query changes the list scroll resets to the top (only the nearest scrollable wrapper, not a surrounding dialog) and not while arrowing through a long list; clearing the query returns highlight and scroll to the selected option |
| LIST-08 | Type-ahead: case-insensitive prefix match that does not depend on locale lowercasing (a Turkish locale still matches "i" to "Istanbul"), Caps Lock does not break it, and it matches non-ASCII letters; buffer resets after about 750 ms, when focus leaves and returns, and when the popup closes; search starts after the active item and wraps; a repeated first letter cycles items unless one starts with a doubled letter, and disabled items are skipped and do not count toward that doubled-letter guard; hidden items are skipped and never block cycling; a repeated multi-letter buffer does not move the highlight until the reset window elapses; a miss clears the buffer, and a match that is only disabled highlights or commits nothing. Matching uses the item's text label (a separate label if given), not decorative content, and skips items with no text. Space extends a non-empty buffer ("Item 2" after "Item ") and otherwise activates; it never activates or opens a submenu while a buffer is active (and does not select in the middle of a typed phrase), and activates again after the menu closes and reopens. A submenu trigger takes part like any item. Ctrl, Meta and Alt are ignored. Matching works with focus on the trigger or on an item |
| LIST-10 | Press timing: a mouseup on a menu item or option activates it only if the press began on the trigger (press-drag-release) and a short time has passed (about 200 ms); a quick release, a release after only small pointer movement, a synthesised mouseup after touch, a release over an option the pointer never hovered, and an opening click that did not start on the item commit nothing; a release over a disabled item focuses it without activating (no click fires); a second non-primary touch never double-commits. A release within about 5 px of the opener's bounds (pseudo-element hit area included) still counts as on it; released more than about 5 px outside the trigger and not on an option, the just-opened popup closes. After a drag-select focus sits on the selected item so arrows continue from it. A context menu opens on right click or after a long press (about 500 ms) cancelled by movement, touch end or a second touch. | LIST-12 | Tab inside an open list: Shift+Tab always closes and returns to the trigger; Tab closes when configured; a Tab that originates from a nested layer (a dialog opened from the menu) does not close the menu |
| LIST-14 | When a popup holds extra focusable controls before the items (a header control, a "Select all" button) and an arrow key is pressed on such a control, then focus enters the items at the list boundary (first item for ArrowDown, last for ArrowUp), not from the previous highlight; if the boundary item is already highlighted, focus moves into it and further arrows continue from there |
| LIST-15 | When a nested submenu closes while the pointer (not the keyboard) drove the interaction and no element in the tree holds focus, then focus moves to the parent popup container so arrow keys keep working there |

## Dialogs, drawers and sheets

| ID | Contract |
| --- | --- |
| DLG-08 | Drawer and sheet follow the same rules. Swipe-to-dismiss has a button alternative, does not block touch drags on native range inputs or sliders, leaves pinch-zoom to the browser, and lets touch scrolling inside scrollable content win over dismissal (see DEV-20 and DLG-12 to DLG-15 for the gesture details). Release dismisses by distance past a threshold, or by an app-supplied rule that sees displacement and velocity |
| DLG-10 | Nested dialogs: only the top one is interactive; closing it returns focus to the dialog that opened it. Dismissing a menu or select inside a dialog does not dismiss the dialog |
| DLG-11 | Drawer default initial focus goes to the popup element; if initial focus is disabled, focus stays on the trigger and the page behind is still not operable |
| DLG-12 | When a touch drag begins over a scrollable area inside a swipe-dismissable layer, then the layer claims the gesture only when the area is already scrolled to the edge matching the dismiss direction (or cannot scroll that way); otherwise the content scrolls and the layer stays put, and after the content reaches that edge during the same drag the swipe may take over. Scrollers on the cross axis are never hijacked, and a drag that never locks to the dismiss axis does not dismiss. When the page itself is the scroller (html or body made a scroll container) it does not block a swipe on a fixed popup, but a scrollable descendant on the other axis of the swipe still blocks it when it is not at its start edge |
| DLG-13 | When a touch gesture has moved less than a few pixels, the layer does not yet cancel native scrolling (cancelling the first touchmove on iOS kills native scroll for the whole gesture); when the browser has already committed the gesture to a native scroll (non-cancelable touchmove) the layer does not reclaim it; once the layer owns the drag it keeps following the finger even if it re-enters the small slop zone or the browser sends non-cancelable moves. A two-finger move (pinch) is never claimed |
| DLG-14 | When a drag on a swipe-dismissable layer is interrupted by a non-primary button press, a context menu, a pointercancel, the popup unmounting, or the layer already being closed while kept mounted, then the swipe state is cleared (no stuck swiping state, no dismissal) and a later release does not close the layer; outside-press dismissal is re-enabled after a context menu interrupts a swipe-open. A tap with no movement or a stationary pointer move never dismisses or opens |
| DLG-15 | When a drawer swipe is released, then dismissal is decided from distance past the threshold or an app-supplied release rule that sees displacement and velocity (px per ms from the latest moving samples; a stationary trailing sample is skipped once, a pause of more than about 80 ms before release or repeated stationary samples drop the velocity to zero, and a press-and-hold does not dilute a later flick); a stale velocity from an earlier gesture is never reused |
